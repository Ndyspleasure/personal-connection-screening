# Scenario / acceptance-criteria coverage matrix

Every acceptance criterion (Brief §56) and the correctness-critical scenarios
(Brief §48–49) mapped to the automated test(s) that enforce it. Test types:
**U** unit, **I** integration (real Postgres), **E2E** booted-app HTTP journey.

Run all: `pnpm test` (U), `pnpm test:integration` (I, needs `DATABASE_URL`),
`pnpm --filter @pcs/e2e test:e2e` (E2E, after `pnpm build`).

## Notes

- The **security suite** (`tests/e2e/src/security.e2e.test.ts`) exercises the
  attack surface end to end against the real booted app: IDOR, replay, fake
  score, safe verification, enumeration, rate limiting.
- Scenarios that require provisioned cloud infrastructure (real Upstash
  distributed limits, Supabase-authenticated admin sessions, production
  migrations) are validated at deploy time — see `docs/deployment.md`.
